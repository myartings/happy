# Update Project Guidance

1. Require an evidenced reusable pattern, bug-prevention rule, or durable decision from completed work.
2. Find the narrowest existing owner: `CONTEXT.md`, an applicable `AGENTS.md`, architecture documentation, an ADR, or another established project guide.
3. Make the smallest durable update, preserving unrelated content and established terminology.
4. Record a new ADR only for a real architectural decision; do not turn an implementation detail into policy.
5. If no reusable learning exists, do nothing.

Do not create a learning receipt, archive, registry, duplicated spec, or periodic audit.
