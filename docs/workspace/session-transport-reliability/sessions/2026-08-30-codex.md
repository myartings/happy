# Session Transport Reliability — Codex handoff

## Outcome

Completed the accepted non-UI transport reliability contract in the isolated
`clever-bridge` worktree without commit, push, merge, deployment, or release.

## Product changes

- CLI outbox batches are FIFO and require acknowledgement of every stable
  `localId` before deletion.
- REST catch-up de-duplicates concurrent Socket delivery, consumes only
  contiguous decryptable sequences, and follows a live cursor past stale pages.

## Test and workflow changes

- Added deterministic CLI disconnect/reconnect, backlog, reorder, duplicate,
  corrupt-record, missing-ack, and live/fetch race tests.
- Added server acknowledgement-loss and absent/reconnecting/dead/silent RPC
  tests with fake clocks.
- Made daemon stress bounded/repeatable and added real new-PID restart with
  persisted Happy/Codex resume identity.
- Full evidence, timings, limitations, and rollback are in `validation.md`.

## Remaining limitation

The repository's real Codex app-server integration on installed Codex 0.150.1
returns no first-turn text before its restart step, so it cannot add live
provider evidence. Deterministic requested-thread and forced-restart coverage
passes; this limitation is not caused by the changed resume code.
